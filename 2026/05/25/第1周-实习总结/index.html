RS485

简介

总结：RS485 = UART串口 + 差分传输芯片 + 方向控制 + 通信协议
RS485 是一种物理电气传输方式，一种电气通信标准，典型的差分信号线，支持较远距离通信。它的常见结构是一个主机，多个从机。此外，RS485 只是传输方式，用户需要确定具体的通信协议，通常有两种选择。
一是：使用 Modbus RTU，这是最推荐的方式，优点是标准化，很多传感器、电机驱动器、PLC 都支持。

RS235与UART

“RS485 的底层是串口”这个说法在工程语境里通常是对的，但从严格定义上说不准确。更准确地说：
RS485 常常承载 UART 串口数据，但 RS485 本身不是 UART，也不是完整的串口协议，而是一种差分电气接口标准。

  • 为什么很多人说“RS485底层是串口”？
    因为在单片机开发里，软件层面的操作还是 UART 串口，我们配置的仍然是波特率、数据位、停止位、校验位。从写程序的人角度看，RS485 经常就是：UART + RS485收发器
  • 事实上，RS485 = UART串口数据 + RS485差分电气传输 + 某种通信协议，很多商家会忽略这一点

总结

RS485 不是自带固定协议的串口，而是串口数据常用的一种远距离、抗干扰、多设备差分传输方式。真正的“协议”通常是 Modbus RTU 或你自己定义的数据帧，并且这些数据是通过串口进行发送。

注意事项

最近使用IIC外设时碰到了一个问题：
问题场景：程序烧入在核心板，IIC外设接在底板上，如果我先给核心板上电，再另外为底板上电，那么IIC外设将会通信失败。反之，如果我先给底板上电，再为核心板上电，IIC外设通信成功。
问题分析：我猜测是因为IIC外设初始化失败。如果先给核心板上电，那么底板上的IIC外设无法及时应答主机发出的信号，进而导致后面的通信失败。反之，先给底板上电，底板IIC外设已处于就绪状态，那么当核心板上电执行程序时，就能及时响应。

引脚复用

简单说，一个物理引脚，不只可以当普通 GPIO 用，也可以连接到芯片内部某个外设功能上。
比如一个引脚既可以作为普通输出控制 LED，也可以作为串口 TX，也可以作为定时器 PWM 输出。你选择其中一种功能使用，这就叫引脚复用。
由于最近接触到的板子都是STM32F1和STM32F4系列，因此这里我们就拿这两个举例

STM32F4系列的引脚复用

STM32F4 的复用方式比 F1 更灵活，也更清晰。F4 系列通常不是用 AFIO Remap，而是给每个引脚指定一个 AF 编号。如：AF0、AF1、AF2、AF3 … AF15。不同 AF 编号对应不同外设功能。
F4 的典型配置逻辑是：

  1. 打开 GPIO 时钟
  2. 设置引脚模式为复用模式 GPIO_Mode_AF
  3. 指定这个引脚连接到哪个 AF 功能
  4. 配置输出类型、速度、上下拉

对比项 STM32F1 STM32F4
复用方式 固定复用 + AFIO 重映射 每个引脚选择 AF 编号
配置关键 GPIO_Mode_AF_PP + GPIO_PinRemapConfig() GPIO_Mode_AF + GPIO_PinAFConfig()
灵活程度 相对固定 更灵活
典型外设选择方式 默认引脚或 Remap 引脚 通过 AF0~AF15 选择
常见例子 USART1 从 PA9/PA10 重映射到 PB6/PB7 PA9 设置 AF7 作为 USART1_TX
