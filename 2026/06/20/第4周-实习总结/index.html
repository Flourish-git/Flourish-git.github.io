环形缓冲区

定义

环形缓冲区，也叫 循环缓冲区 / Ring Buffer / Circular Buffer，本质上是一块固定大小的数组空间，但它的读写方式像一个“首尾相接的圆环”。
它通常用两个指针或下标管理：

名称 作用
写指针 / write / head 指向下一次写入数据的位置
读指针 / read / tail 指向下一次读取数据的位置
缓冲区数组 存放临时数据

运作方式：

  • 当写入数据时，head向前移动；当读取数据时，tail向前移动。
  • 当写指针写到数组末尾时，不是停止，而是重新回到数组开头继续写(通常通过取模运算实现)。
    例如缓冲区大小为 8：

如果写到 buf[7] 后，下一次写入会回到：

所以它看起来像一个环。

作用及使用场景

在嵌入式系统中，环形缓冲区最常见的作用是：

临时存放来不及立即处理的数据，实现“接收”和“处理”的解耦。

也就是说，数据来的时候先放进缓冲区，主程序有空时再慢慢取出来处理。

场景 环形缓冲区的作用
串口接收 UART 中断中快速把收到的字节存入缓冲区，主循环再解析
串口发送 UART 主程序把要发的数据放入缓冲区，中断/DMA慢慢发送
I2C / SPI 数据缓存 临时保存主从机通信数据
ADC 采样 保存一段连续采样数据，方便滤波或平均
按键事件队列 保存按键事件，避免漏按
传感器数据缓存 暂存传感器连续输出的数据

其中最典型的是 串口接收缓冲区。
因为嵌入式系统经常会遇到这种情况：

问题 环形缓冲区的好处
数据来得快，处理来不及 先缓存，避免丢数据
中断函数不能写太长 中断只负责存数据，主循环再处理
内存有限 使用固定数组，不频繁申请释放内存
数据是连续流式的 适合串口、ADC、传感器等连续数据
需要 FIFO 顺序 先写入的数据先被读取

环形缓冲区通常是 FIFO 结构：

先进先出，先来的数据先处理。
